# 타슈 수요예측 추론 파이프라인 정리

> 대상 코드: `inference/tashu_predict.py`
> 실행: `python tashu_predict.py ST0065`
> 예측 범위: **다음 정시 ~ 내일모레(D+2) 23시** (예: 지금 09:37이면 오늘 10시부터 내일모레 23시까지, 약 62개 시각)

---

## 1. 전체 흐름 한눈에

```
[입력]  station_id  (예: ST0065)
   │
   ├─(1) 기상청 단기예보 API 1회 호출  → 시각별 날씨 (temp/humid/wind/precip)
   ├─(2) 에어코리아 대기질 API 1회 호출 → 현재 대기질 (pm10/pm25/ozone)
   │
   ▼
[피처 조립]  예측 시각마다 1행 생성
   = 스테이션(1) + 시간 파생(5) + 날씨(4) + 대기질(3) = 총 13개 피처
   │
   ▼
[모델]  LightGBM 2개  (대여용 / 반납용, objective=poisson)
   │  predict() 각 1회 → 행 전체 한 번에 예측
   ▼
[출력]  시각별  time · rent(대여) · return(반납) · net(rent−return)
```

- 입력은 **스테이션 ID 하나**뿐. 시각·날씨·대기질은 코드가 알아서 채운다.
- 스테이션이 몇 개든, 며칠 예측이든 **외부 API 호출은 항상 2번**(격자·측정소 단위라 위치 무관).
- 모델 호출도 **대여 1회 + 반납 1회 = 2번** (여러 시각을 한 DataFrame으로 한꺼번에 예측).

---

## 2. API 호출 상세

두 API 모두 **data.go.kr(공공데이터포털)** 인증키 1개로 호출한다. (각 API별 '활용신청' 승인 필요)

### (1) 기상청 단기예보 — `fetch_forecast()`

| 항목 | 내용 |
|---|---|
| 엔드포인트 | `.../VilageFcstInfoService_2.0/getVilageFcst` |
| 제공 범위 | 발표시각 기준 **최대 +3일**, 시각별 예보 |
| 발표시각 | 하루 8회: **02·05·08·11·14·17·20·23시** (그 외 시각으로 호출하면 에러) |
| 위치 지정 | 기상청 **격자좌표 `nx=68, ny=100`** (대전역 격자 — 위경도 변환 검증 완료) |

**호출 파라미터**
```
serviceKey, dataType=JSON,
base_date=YYYYMMDD, base_time=HH00,   ← "가장 최근 발표분"을 자동 계산 (_forecast_base)
nx=68, ny=100,
numOfRows=1000, pageNo=1              ← 3일치 전 항목 약 871건 → 한 페이지에 다 담김
```

**base_time 자동 선택 로직**: 현재시각에서 15분(발표~제공 지연 여유) 뺀 뒤, 위 8개 발표시각 중 지나간 최신 슬롯을 사용. (자정~02시대는 전날 23시 발표분)

**응답 → 사용 항목 매핑** (응답은 시각×항목 낱개 행으로 옴 → `(fcstDate, fcstTime)` 키로 재조립)

| 우리 컬럼 | 단기예보 category | 비고 |
|---|---|---|
| `temp` | `TMP` | 1시간 기온(℃) |
| `humid` | `REH` | 습도(%) |
| `wind` | `WSD` | 풍속(m/s) |
| `precip` | `PCP` | 강수량 — 텍스트를 숫자로 변환: `'강수없음'`→0, `'1mm 미만'`→0.5, `'30.0~50.0mm'`→50 등 |

> 예측 시각이 예보 커버리지 밖(먼 미래)이면 **직전 시각 값으로 채움**(forward-fill)하여 결과가 끊기지 않게 함.

### (2) 에어코리아 대기오염정보 — `fetch_air()`

| 항목 | 내용 |
|---|---|
| 엔드포인트 | `.../ArpltnInforInqireSvc/getMsrstnAcctoRltmMesureDnsty` |
| 위치 지정 | 측정소명 **`성남동1`** (대전, 격자 (68,100)과 동일 동네) |
| 특징 | **미래 예보가 없음** → 최근 관측값을 미래에 그대로 사용(persistence 근사) |

**호출 파라미터**
```
serviceKey, returnType=json,
stationName=성남동1, dataTerm=DAILY, numOfRows=24, ver=1.3
```

**응답 → 사용 항목 매핑** (통신장애 `'-'` 값은 건너뛰고 **최신 유효값 1개씩** 추출)

| 우리 컬럼 | 응답 필드 | 비고 |
|---|---|---|
| `pm10` | `pm10Value` | 미세먼지 |
| `pm25` | `pm25Value` | 초미세먼지 |
| `ozone` | `o3Value` | 오존 |

> 이 **현재값 1세트를 모든 예측 시각에 동일하게 복사**해서 사용. (3일 내내 대기질은 고정값)

---

## 3. 파생 피처 (시각 정보에서 계산)

API와 무관하게, **예측 대상 시각(datetime)만으로 계산**하는 피처.

| 피처 | 계산 방법 | 예 |
|---|---|---|
| `hour` | 시각의 시(0~23) | 10 |
| `dow` | 요일 (월=0 … 일=6) | 0 |
| `is_weekend` | 토·일이면 1, 아니면 0 (`dow >= 5`) | 0 |
| `month` | 월(1~12) | 7 |
| `is_holiday` | 한국 공휴일(`holidays.KR`)이거나 임시공휴일이면 1 | 0 |

`station_id`는 입력값을 그대로 쓰되, 학습과 동일하게 **범주형(Categorical, 19개 고정 순서)**으로 인코딩한다.

---

## 4. 최종 입력 피처 (총 13개)

한 행 = "특정 스테이션 × 특정 시각". 예측 시각 수만큼 행이 쌓인다.

| # | 피처 | 출처 | 설명 |
|---|---|---|---|
| 1 | `station_id` | 입력 | 스테이션 ID (범주형) |
| 2 | `hour` | 파생 | 시(0~23) |
| 3 | `dow` | 파생 | 요일(0~6) |
| 4 | `is_weekend` | 파생 | 주말 여부 |
| 5 | `month` | 파생 | 월 |
| 6 | `is_holiday` | 파생 | 공휴일 여부 |
| 7 | `temp` | 기상청 API | 기온 |
| 8 | `humid` | 기상청 API | 습도 |
| 9 | `wind` | 기상청 API | 풍속 |
| 10 | `precip` | 기상청 API | 강수량 |
| 11 | `pm10` | 에어코리아 API | 미세먼지 |
| 12 | `pm25` | 에어코리아 API | 초미세먼지 |
| 13 | `ozone` | 에어코리아 API | 오존 |

- **입력(1) + 파생(5) + 날씨(4) + 대기질(3) = 13**
- 참고: 학습 시 피처 중요도는 `station_id > hour > temp` 순. `is_weekend`는 사실상 미사용(요일과 중복).

---

## 5. 모델 & 출력

### 모델
- **LightGBM 회귀 2개** — 대여용(`model_rent_v1.pkl`), 반납용(`model_return_v1.pkl`)
- `objective='poisson'` (0이 많은 카운트 데이터에 적합)
- 학습 성능(test=2026-02): 대여 MAE 0.461 / 반납 MAE 0.469, R² 0.49

### 출력
위 13피처 DataFrame을 두 모델에 각각 넣어 시각별 예측값을 얻는다.

| 컬럼 | 의미 |
|---|---|
| `time` | 예측 시각 (예: `07-20 10시`) |
| `rent` | 그 시각 예상 **대여 건수** |
| `return` | 그 시각 예상 **반납 건수** |
| `net(rent-return)` | 대여 − 반납. **+면 자전거 유출(부족 위험), −면 유입(과잉)** |

**출력 예시** (ST0065, 실제 실행)

```
[ST0065] 다음 정시 ~ 내일모레 23시 수요 예측
     time  rent  return  net(rent-return)
07-20 16시  6.09    4.66              1.43
07-20 17시  6.62    4.68              1.94   ← 저녁 피크(유출)
07-21 06시  1.80    6.83             -5.03   ← 아침 반납 몰림(유입)
 ...
07-22 23시  2.05    1.32              0.73
```

- 값 패턴이 실제 이용 특성과 일치: **16~18시 대여 피크**, **새벽 3~4시 최저**, **아침 출근시간 반납 몰림**.
- `net` 누적을 활용하면 "언제·어느 스테이션이 부족/과잉" → **재배치 의사결정**으로 확장 가능.

## 6. 한계 (보고 시 함께 명시 권장)

1. **예측 범위가 3일까지** — 기상청 단기예보가 +3일까지만 제공하기 때문(약점이 아니라 서비스 스펙).
2. **대기질은 현재값 근사** — 미세먼지는 미래 예보 자체가 없어 현재 관측치를 그대로 사용 → 먼 시각일수록 신뢰도 낮음.
3. **일부 스테이션 오차 큼** — 예: ST1302는 수요 대비 오차가 상대적으로 높음(별도 표시 권장).
